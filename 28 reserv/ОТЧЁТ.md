## Версия 0.31 от 2026-11-23 — Мульти-режим для Pine-сигналов

### Изменения:

1. **Мульти-режим для Pine-сигналов (как у фракталов)**
   - `mode === 'off'` → одна позиция (LONG или SHORT) до закрытия
   - `mode === 'add'` → добавление позиций по новым сигналам
   - `mode === 'exclude'` → исключение противоположных позиций

2. **Единая логика для фракталов и Pine**
   - Оба типа сигналов используют одинаковый `multiModeConfig`
   - `handleSignal()` вызывается для `'add'` и `'exclude'` режимов
   - `openPosition()` вызывается только для `'off'` режима

3. **Бэктест Pine — лог мульти-режима**
   - Добавлен расширенный лог запуска с указанием режима
   - Пример: `maxOpen=3 (до 3 (add))` или `maxOpen=1 (1 позиция)`

### Различия Live vs Бэктест:

| Компонент | Live-режим | Бэктест |
|---|---|---|
| **Мульти-режим** | `handleSignal()` (полная логика) | `openPositions.length < maxOpen` (упрощённая) |
| **sameSideRisk** | ✅ Учитывается | ❌ Не учитывается |
| **excludeOnlyOpposite** | ✅ Учитывается | ❌ Не учитывается |
| **lossStreak** | ✅ Учитывается | ❌ Не учитывается |
| **maxOpen** | 1 (off) / ∞ (add/exclude) | 1 (off) / 3 (add/exclude) |

**Почему:** Бэктест работает на исторических данных (`chartBars`), а `handleSignal()` требует `realTimeBars` и `currentPrice`. Упрощённая логика бэктеста даёт **приблизительные** результаты для `'add'`/`'exclude'` режимов.

### Версия UI:
- Обновлена с 0.30 до 0.31

### Changelog:
- **Исправлено:**
  - Мульти-режим не работал для Pine-сигналов (использовалась только логика фракталов)
  - Pine-сигналы теперь работают идентично фракталам в live-режиме

   - Логика:
     - Берёт последние 100 баров для оптимизации

     - Открывает позицию с настройками из UI (риск, SL, TP, мульти-режим)

   - Логирование: "🟢 Pine LONG | цена: X | SL: Y | TP: Z"

   - Порядок обработки: сначала фракталы, потом Pine-сигналы
   - Оба типа сигналов работают независимо

   - `saveProfile()`: `strategyFlags.pineSignalsEnabled` сохраняется автоматически
