# Conflict Detect (Обнаружение конфликтов)

**Когда использовать:** ДОБАВЛЕНИЕ новых функций, кнопок UI, полей JSON, скриптов — проверка на пересечение с существующими.

**Цель:** Предотвратить конфликты имён, дублирование логики, пересечение функций.

---

## Пошаговая инструкция

### 1. ПЕРЕД добавлением новой функции
- [ ] Проверить уникальность имени (`grep_search` по `function name`)
- [ ] Если имя занято → предложить альтернативу (`newName_v2`, `newNameUpdated`)
- [ ] Проверить, что функция НЕ пересекается с существующей логикой

### 2. ПЕРЕД добавлением кнопки UI
- [ ] Проверить уникальность ID (`grep_search` по `id="buttonId"`)
- [ ] Если ID занят → предложить альтернативу (`buttonId2`, `buttonIdNew`)
- [ ] Проверить, что кнопка НЕ дублирует существующую функцию

### 3. ПЕРЕД добавлением поля JSON
- [ ] Проверить уникальность имени (`grep_search` по `fieldName`)
- [ ] Если имя занято → проверить тип (может быть другое поле с таким именем)
- [ ] Проверить, что поле НЕ пересекается с существующей логикой

### 4. ПЕРЕД добавлением скрипта
- [ ] Проверить уникальность функций в скрипте (`grep_search` по `window.functionName`)
- [ ] Если функции уже есть → предложить альтернативу или удалить старые
- [ ] Проверить, что скрипт НЕ конфликтует с существующими

### 5. ПОСЛЕ добавления
- [ ] Проверить целостность файла (строки, скобки, `node -c`)
- [ ] Протестировать новую функцию (если применимо)
- [ ] Убедиться, что старые функции работают

---

## Правила пользователя

1. **ВСЕГДА проверять уникальность** — имена функций, ID кнопок, поля JSON
2. **Предлагать альтернативы** — если имя занято (`newName_v2`, `newNameNew`)
3. **Избегать дублирования** — НЕ создавать функции с одинаковой логикой
4. **Проверять пересечения** — новая функция НЕ должна конфликтовать с существующей
5. **Тестировать** — после добавления проверить, что всё работает

   ```
   grep_search: __longBacktestRunner

   ```

**Результат:** Функция доступна в панели запуска без конфликтов.

## Плохой пример

### ❌ Пример: Дублирование `resetAccount()` (2026-11-17)

**Задача:** Исправить сброс статистики

**Что сделано НЕПРАВИЛЬНО:**
1. ❌ НЕ проверена уникальность имени
2. ❌ Создана новая функция `resetAccount()` (старая уже существует)
3. ❌ НЕ предложена альтернатива
4. ❌ Конфликт имён → старая функция вызывается вместо новой

**Симптом:** Статистика НЕ сбрасывается после нажатия кнопки

**Причина:** Две функции с одинаковым именем — вызывается первая (старая)

**Как исправить:**
- ВСЕГДА проверять уникальность (`grep_search`)
- Если имя занято → предлагать альтернативу (`_resetAccountInternal`)
- Использовать префиксы (`_`, `__`) для внутренних функций
