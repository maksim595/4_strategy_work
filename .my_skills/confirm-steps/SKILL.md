# Confirm Steps (Пошаговое подтверждение изменений)

**Когда использовать:** КАЖДОЕ редактирование файлов по запросу пользователя — добавление функций, кнопок UI, исправление багов, рефакторинг.

**Цель:** Предотвратить ошибки из-за неполного понимания задачи, дать пользователю контроль над каждым этапом.

---

## Пошаговая инструкция

### 1. ПОЛУЧЕНИЕ первого указания
- [ ] Прочитать ВСЕ указанные файлы (`read_file` с limit=50-100)
- [ ] Подтвердить понимание: «Принято. Ознакомился с файлами...»
- [ ] Записать первый пункт в накопительный список
- [ ] Ждать следующее указание (НЕ применять правки!)

### 2. ПОЛУЧЕНИЕ следующего указания
- [ ] Повторить ВЕСЬ накопительный список (нумерованный, с таблицей статусов)
- [ ] Добавить новый пункт
- [ ] Подтвердить готовность: «Готов принять следующий пункт»
- [ ] Ждать следующее указание (НЕ применять правки!)

### 3. ПОЛУЧЕНИЕ команды «пора делать правки»
- [ ] Показать ФИНАЛЬНЫЙ список всех пунктов (таблица: № | Файл | Изменение | Статус)
- [ ] Применять правки ТОЧЕЧНО (по одному `edit()` на пункт)
- [ ] После КАЖДОЙ правки: проверка целостности (скобки, строки, `node -c`)
- [ ] Обновить статус в таблице: «✅ ВНЕДРЕНО» или «❌ ОШИБКА»

### 4. ЕСЛИ ошибка при правке
- [ ] НЕ продолжать следующие пункты
- [ ] Сообщить об ошибке (строка, баланс скобок, `node -c` вывод)
- [ ] Ждать указаний пользователя (исправить / пропустить / откатить)

### 5. ПОСЛЕ всех правок
- [ ] Передать список всех правок в навык `final-report`
- [ ] Убедиться, что ОТЧЁТ.md дополнен ВСЕМИ пунктами
- [ ] Проверить версию UI в отчёте

---

## Правила пользователя

1. **Накопительный список** — повторять ВСЕ пункты при каждом новом указании
2. **Таблица статусов** — визуально показывать: ✅ ВНЕДРЕНО | ⏳ ОЖИДАЕТ | ❌ ОШИБКА
3. **Явное подтверждение** — ждать команду «пора делать правки» перед применением
4. **Точечные правки** — избегать избыточного дублирования (не копировать целые функции)
5. **Проверка конфликтности** — новые функции не должны пересекаться с существующими
6. **Передача в final-report** — после применения всех правок передать накопительный список в навык `final-report`

## Плохой пример

### ❌ Пример: Пропуск подтверждения (2026-11-03)

**Задача:** Пользователь дал 3 пункта подряд

**Что сделано НЕПРАВИЛЬНО:**
1. ❌ НЕ повторил накопительный список после 2-го пункта
2. ❌ НЕ показал таблицу статусов
3. ❌ Применил правки БЕЗ команды «пора делать правки»
4. ❌ Пункт 3 применён с ошибкой (файл усечён до 443 строк)

**Симптом:** Пользователь спросил «Ты случайно не затёр мою восстановленную версию?»

**Причина:** ИИ пропустил этап подтверждения → не заметил, что `old_string` встречается 2 раза

**Как исправить:**
- ВСЕГДА повторять весь список перед новым пунктом
- Ждать явную команду «пора делать правки»
- Проверять баланс `{}` ПЕРЕД `edit()`
