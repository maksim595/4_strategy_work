# Final Report (Финальный отчёт)

**Когда использовать:** ПОСЛЕ завершения всех правок — создание/дополнение ОТЧЁТ.md, обновление версии UI, changelog.

**Цель:** Документировать ВСЕ изменения — пользователь может проверить, что ни одна правка не потеряна.

**КРИТИЧЕСКИ ВАЖНО:** Включать ВСЕ правки, даже минимальные (добавление кнопки, перемещение элемента).

---

## Пошаговая инструкция

### 1. ПОСЛЕ всех правок
- [ ] Найти существующий `ОТЧЁТ.md` (`grep_search`)
- [ ] Если нет → создать новый
- [ ] Прочитать последние 2 раздела (limit=50)

### 2. ДОБАВЛЕНИЕ нового раздела
- [ ] Добавить заголовок: `## Версия X.XX от YYYY-MM-DD`
- [ ] Перечислить ВСЕ изменения (по пунктам, с номерами)
- [ ] Указать новую версию UI (если обновлялась)
- [ ] Добавить changelog (Добавлено / Изменено / Исправлено)

### 3. ПРОВЕРКА полноты
- [ ] Сверить с накопительным списком изменений из `confirm-steps` (все ли пункты вошли)
- [ ] Проверить, что каждая правка описана (даже минимальная)
- [ ] Убедиться, что версия UI обновлена
- [ ] Если правки не вошли → добавить раздел «Пропущенные правки»

### 4. ЕСЛИ правки не вошли в отчёт
- [ ] Добавить отдельный раздел «Пропущенные правки»
- [ ] Перечислить недостающие изменения
- [ ] Сообщить пользователю: «В ОТЧЁТ.md добавлены пропущенные правки»

### 5. ПОСЛЕ создания отчёта
- [ ] Сохранить резервную копию ОТЧЁТ.md
- [ ] Проверить целостность (баланс `{}`, закрывающие теги)

---

## Правила пользователя

1. **ВСЕ правки в отчёт** — даже минимальные (перемещение кнопки, исправление опечатки)
2. **Версия UI** — обновлять при каждом изменении интерфейса (кнопки, панель запуска)
3. **Changelog** — группировать: Добавлено / Изменено / Исправлено
4. **Нумерация** — сквозная нумерация пунктов (1, 2, 3...)
5. **Дата** — указывать дату создания отчёта (YYYY-MM-DD)
6. **Сверка с confirm-steps** — ВСЕГДА сверять с накопительным списком из `confirm-steps`

## Хорошие примеры

### ✅ Пример 1: Отчёт после исправления таймера (2026-11-17)

**Задача:** Исправить таймер, добавить кнопку, переместить кнопки профиля

**Действия:**
1. Найден `ОТЧЁТ.md` (существующий)
2. Добавлен раздел:
   ```markdown
   ## Версия 0.25 от 2026-11-17
   
   ### Изменения:
   1. Исправлен таймер — отсчёт от `startTime=Date.now()` (как в fractal_bot_v0.7.1)
   2. Добавлена кнопка «🔍 Обновить график» (масштабирование по X и Y)
   3. Кнопки «💾 Сохранить профиль» и «📥 Загрузить профиль» перемещены в верхнюю панель
   4. Исправлен сброс статистики — `_resetAccountInternal()` очищает ДО закрытия позиций
   5. Добавлен явный экспорт `backtestMultiSymbolLong` через `window.__longBacktestRunner`
   
   ### Версия UI:
   - Обновлена с 0.24 до 0.25
   
   ### Changelog:
   - Добавлено: кнопка «🔍 Обновить график», панель запуска скрипта
   - Изменено: логика таймера (`startTime` вместо `lastBarTime`)
   - Исправлено: сброс статистики (`_resetAccountInternal`), таймер при загрузке
   ```
3. Проверка: все 5 пунктов из накопительного списка вошли в отчёт

**Результат:** ОТЧЁТ.md дополнен, версия UI обновлена.

### ✅ Пример 2: Отчёт после добавления JSON полей (2026-11-17)

**Задача:** Добавить `trailingEnabled` и `__longBacktestRunner` в профиль

**Действия:**
1. Найден `ОТЧЁТ.md`
2. Добавлен раздел:
   ```markdown
   ## Версия 0.25 от 2026-11-17 (дополнение)
   
   ### Изменения:
   1. В `saveProfile()` добавлено: `settings.trailingEnabled`
   2. В `loadProfile()` добавлено: загрузка `trailingEnabled` с проверкой `!== undefined`
   3. Добавлена функция `window.__longBacktestRunner` для панели запуска
   4. В `collectScriptParams()` добавлены параметры для `__longBacktestRunner`
   
   ### Версия UI:
   - Без изменений (0.25)
   
   ### Changelog:
   - Добавлено: `trailingEnabled` в JSON профиль, `__longBacktestRunner`
   - Изменено: `saveProfile()`, `loadProfile()`
   - Исправлено: потеря настройки `trailingEnabled` при загрузке
   ```
3. Проверка: все 4 пункта вошли в отчёт

**Результат:** ОТЧЁТ.md дополнён, JSON настройки задокументированы.

## Плохой пример

### ❌ Пример: Отчёт без всех правок (2026-11-03)

**Задача:** Дополнить ОТЧЁТ.md после 5 правок

**Что сделано НЕПРАВИЛЬНО:**
1. ❌ Включены только 3 правки из 5
2. ❌ НЕ указана версия UI (осталась 0.24)
3. ❌ Changelog пустой
4. ❌ 2 правки (перемещение кнопок, добавление экспорта) НЕ вошли

**Симптом:** Пользователь спросил: «А где правки про кнопки и экспорт?»

**Причина:** ИИ забыл включить все правки в отчёт

**Как исправить:**
- ВСЕГДА сверять с накопительным списком изменений
- Включать КАЖДУЮ правку (даже перемещение кнопки)
- Указывать версию UI при каждом изменении интерфейса
- Заполнять Changelog (Добавлено / Изменено / Исправлено)
